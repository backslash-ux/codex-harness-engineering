# v1.1.0 release candidate

Publication status: not published. Local checks do not establish public release,
GitHub branch protection, or installation state.

## Changes

- Initialization preflights its complete destination set, rejects redirected
  destinations, creates files exclusively, and applies establishment/dirty guards
  whenever new files would be created. Complete identical reruns remain no-ops.
- Global contract replacement uses unique temporary files and preserves existing
  permissions. Reversed managed markers receive a controlled diagnostic.
- Command discovery includes documented Python commands and script references.
  Additive command evidence records source lines, working directories, configured
  CI invocation, failure propagation, and unverified merge requirements.
- Scoped override/fallback guidance and explicit profile declarations are shared
  across alignment, inspection, and validation. Conflicts remain advisory but
  require input before a profile-dependent decision.
- Comprehensive audits may report all material findings; routine alignment keeps
  one smallest recommendation. Development-only live evaluations compare twelve
  representative scenarios without entering the plugin archive.

## Compatibility and limitations

Python 3.10+ and no runtime dependencies are preserved. Existing CLI flags,
exit conventions and JSON fields remain. Read-only commands add `--scope` and
repeatable `--fallback-guidance`; initialization also accepts fallback filenames
to detect competing guidance. New structured evidence is additive.

CI inspection supports a conservative GitHub Actions/shell subset. Conditional,
non-blocking, unsupported or ambiguous execution remains unverified. It does not
execute commands, contact providers, or infer merge requirements. Host-specific
configuration loading and context truncation are not emulated.

Existing user guidance and installed plugin caches are never rewritten during a
repository upgrade. Changed managed blocks remain protected by divergent-content
refusal; any migration of existing global guidance needs an explicitly reviewed
target/content change. Written rules do not substitute for host or provider gates.

## Publication checklist

1. Complete local matrix checks, validators, independent review and bounded agent
   comparison; inspect the final diff for private content and unintended changes.
2. Obtain authorization for push/provider operations. Capture existing main-branch
   policy and prepare update and restoration payloads outside the repository.
3. Require PRs and Python 3.10/3.13 checks with an up-to-date branch, no force push,
   deletion or admin bypass, and zero additional approving reviewers. Verify the
   provider readback independently of workflow success.
4. Verify CI for the final candidate commit and obtain owner merge/release approval.
5. Publish an immutable v1.1.0 tag and deterministic archive. Read back the tag,
   release asset checksum, and tagged installation instructions. Record installed
   version separately; no installation is implied by publication.

If a release defect appears, suspend the affected mutation command and prepare a
corrective patch. Do not silently return users to the known-vulnerable baseline.
